# Portal 共享图标支付选择器设计

## 目标

让门户购买页和控制台余额充值页使用同一套简洁的支付方式选择界面：只展示 PayPal 与 TRC20-USDT，两者以本地图标识别，同时保留各自的说明和“继续支付”按钮。

## 组件边界

`PaymentSelectionPanel` 继续是唯一的金额选择和支付订单创建组件。`PurchasePage` 与 `RechargePage` 只负责页面容器、订单完成后相应的结账视图及返回操作；它们不得复制支付卡、金额状态或下单逻辑。

## UI 行为

- 金额预设、自定义金额校验、所选金额摘要和提交中禁用逻辑保持不变。
- 支付区域只渲染 PayPal 和 TRC20-USDT 卡片，删除“其他支付方式”和“即将开放”信息。
- PayPal 卡使用 `src/public/Paypal.png`，TRC20 卡使用 `src/public/Tron.png`；图片提供准确的替代文本，加载失败时不阻止文字和按钮使用。
- 每张卡保留渠道名称、现有说明与专属继续按钮。按钮继续调用现有 `handleMethod`，分别提交 `PAYPAL` 与 `USDT_TRC20`，不允许图标或卡片本身创建订单。
- 共享样式在桌面端将两张卡等宽排列，在窄屏变为单列；不影响 PayPal/TRC20 的后续结账组件。

## 验证

先修改门户购买与控制台充值测试，要求两页都显示两张带替代文本的图标卡、没有“其他支付方式”，且点击继续支付仍发送原有方法和金额。确认测试失败后，实施 JSX 和样式，运行相关 Vitest、全量前端测试与生产构建。
