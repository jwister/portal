# 支付订单恢复处理设计

## 背景与目标

用户在 TRC20-USDT 支付页完成链上转账后，可能在提交 TxID 前刷新或关闭页面。订单仍处于“等待支付”，但现有订单管理页只能展示记录，用户无法补交 TxID，也无法主动取消不再使用的待支付订单。

本设计以订单管理页为恢复入口：用户双击订单行后进入订单详情弹窗。在不改变订单归属和支付状态的前提下，为待支付订单提供安全、可恢复的操作。

## 范围

### 包含

- 双击订单列表任意订单行，打开订单详情弹窗。
- 展示订单号、金额、额度、支付方式、创建时间、到期时间和状态。
- 所有支付方式的 `WAITING_PAYMENT` 订单均可取消。
- `WAITING_PAYMENT` 的 `USDT_TRC20` 订单可查看支付地址、精确应付金额，并补交或重新提交 TxID。
- 操作成功后刷新弹窗数据和订单列表。
- 后端使用当前登录会话校验订单归属，并在事务锁内重新校验订单状态。

### 不包含

- 修改 PayPal 支付流程或为 PayPal 增加恢复支付动作。
- 修改 TRC20 链上扫描、自动核验和到期调度逻辑。
- 对非待支付订单执行取消、TxID 提交或其他状态回退。

## 交互设计

订单列表保留既有展示和分页。用户双击任意行时打开“订单详情”弹窗：

1. 所有订单均以只读方式展示基础信息。
2. 当状态为 `WAITING_PAYMENT` 时显示“取消订单”按钮，并在二次确认后提交取消。
3. 当订单同时满足 `method = USDT_TRC20` 和 `status = WAITING_PAYMENT` 时，弹窗额外展示收款地址、精确 USDT 金额、TxID 输入和“提交并核验”按钮。TxID 可重新提交，提交后显示服务端返回的最新核验结果。
4. 已确认、入账中、已支付、已过期、已取消、入账异常等非待支付状态只读；前端隐藏取消和 TxID 操作。
5. 后端返回状态变化或错误时，前端以明确提示反馈，并重新读取订单状态，避免用户在订单到期或被并发处理后继续看到过时操作。

## 后端设计

新增受登录保护的取消订单端点：`POST /api/payments/orders/{orderNo}/cancel`。

取消服务的职责：

1. 依据 session principal 获取当前门户用户，禁止客户端传入用户 ID。
2. 在事务内锁定并读取订单，确认订单归属当前用户。
3. 仅允许 `WAITING_PAYMENT` 状态取消；过期、已确认、入账中、已支付、已取消或异常订单返回业务错误。
4. 调用领域对象现有的 `PaymentOrder.cancel(now)`，持久化为 `CANCELLED` 并返回最新订单视图。

现有 TRC20 状态查询与 TxID 提交端点继续使用。订单详情恢复界面只传递订单号和 TxID；支付地址、金额、状态、用户归属均由服务端订单数据决定。

## 前端设计

`OrdersPage` 增加所选订单和详情弹窗状态。双击事件传入当前行的订单号，打开详情并查询 TRC20 状态（仅 TRC20 订单）。

前端 API 层新增取消订单调用，并复用现有的 TRC20 状态查询、TxID 提交类型和请求。支付信息展示与现有 `Trc20Checkout` 的字段、格式化方式保持一致，避免产生两套金额和地址语义。

成功取消或提交 TxID 后：刷新详情数据与订单列表；当订单不再满足可操作条件时立即隐藏相应操作。取消请求发送期间禁用重复点击；TxID 请求发送期间禁用重复提交。

## 安全与并发

- 前端显示条件仅改善体验，不承担授权职责。
- 每次取消和 TxID 提交均由后端使用当前会话确认订单归属。
- 取消采用数据库锁与状态二次校验，防止支付确认、到期任务和用户取消并发时写入非法状态。
- 客户端不得决定金额、地址、币种、订单状态或用户标识。

## 错误处理

- 订单不存在或不属于当前用户：返回与现有订单查询一致的不可访问结果，不泄露其他用户订单信息。
- 已不处于待支付状态：返回明确业务错误；前端刷新详情及列表。
- 取消或 TxID 提交网络失败：保留用户输入，展示错误并允许重试。
- TRC20 核验未找到交易、确认数不足、金额/地址不匹配、TxID 重复等结果由既有服务返回并原样映射为本地化提示。

## 测试策略

- 后端：待支付且归属当前用户的取消成功；非归属订单、非待支付订单取消失败；取消后状态为 `CANCELLED`。
- 前端：双击打开详情；待支付订单显示取消；非待支付订单只读；TRC20 待支付订单显示并可提交 TxID；非 TRC20 订单不显示 TxID 操作；成功操作会刷新列表。

## 验收标准

用户可在刷新或关闭支付页后，从订单管理中双击打开待支付 TRC20 订单并补交 TxID；所有待支付订单可由所属用户取消。任何非待支付订单和任何非所属订单都不能被取消或被补交 TxID。
