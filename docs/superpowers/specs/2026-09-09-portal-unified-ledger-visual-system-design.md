# Portal Unified Ledger 全站视觉系统设计

## 目标

将 Ztoken Portal 的首页、模型、购买、认证页和控制台统一为同一套 "Unified Ledger" 视觉语言：暖白纸张背景、深墨绿内容、森林绿主操作和账本式信息卡。现有功能、路由、认证、支付、请求与数据展示行为不变。

## 页面范围

- 公共：首页、模型目录/详情、购买/结账、登录、注册、公共导航与页脚。
- 控制台：侧栏、顶栏、仪表盘、充值、密钥、日志、订单、个人资料及其加载、错误、空数据状态。
- 不修改：后端 API、翻译文案语义、支付订单和链上核验逻辑、权限模型和路由结构。

## 共享令牌

全局样式定义一组主题变量，并由公共页和控制台同时消费：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ledger-paper` | `#f4f6f0` | 页面与大区背景 |
| `--ledger-surface` | `#fffefb` | 卡片、导航和表格表面 |
| `--ledger-ink` | `#183128` | 标题与主要文本 |
| `--ledger-muted` | `#61746a` | 次级内容 |
| `--ledger-green` | `#147b57` | 主操作、选中和活跃状态 |
| `--ledger-line` | `#d5dfd6` | 边框与分隔线 |

成功、等待、人工审核和失败状态继续使用语义颜色：成功为绿色、审核为琥珀色、失败/过期为红色；不得以统一主题色覆盖这些状态。

## 版式与组件

公共页使用固定导航下的纸张背景、Georgia 标题和受控留白。首页的主视觉、数据指标、能力卡、接入步骤和 CTA 收敛为与模型/购买相同的边线、圆角和阴影尺度。认证页面使用窄列账本表单和清晰的错误区域。

控制台保留侧栏与高密度内容架构，但侧栏、顶栏、内容背景、数据卡、表格工具栏、表单、充值选择和结账摘要全部使用同一令牌。桌面端控制台维持白色分栏；手机端继续收起侧栏且保证顶栏、筛选与卡片不重叠。

支付选择继续由 `PaymentSelectionPanel` 提供，门户购买和控制台充值不会分叉。充值页仅调整外观与页面容器，不改变 PayPal 或 TRC20 的后续行为。

## 可访问性与响应式

- 保留所有现有 heading、按钮名称、aria 标签、表单 label、错误 alert 和键盘路径。
- 颜色不单独传达支付或订单状态；文字状态继续存在。
- 760px 以下公共卡片与控制台内容改为单列，当前移动导航防重叠规则继续只作用于公共账本页面。
- 所有悬停位移与入场动画遵守 `prefers-reduced-motion`。

## 验证

实现前，补充 App 壳、首页和控制台充值测试来锁定 Unified Ledger 主题挂载及共享充值结构；实施后运行全部 Vitest、生产构建，并在桌面与 375px 视口检查公共页、认证页、模型页、购买页、控制台仪表盘与充值页。任何视觉调整不得改变下单 payload、支付 SDK URL 或订单状态颜色。
