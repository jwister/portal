# Portal 支付确认选择器设计

## 目标

将门户购买和控制台余额充值共用的支付选择组件简化为图标文字单选卡和一个统一的确认支付按钮，并让充值说明与订单预计入账金额使用用户可理解的美元显示。

## 支付选择

`PaymentSelectionPanel` 继续是两个页面唯一的金额和支付订单创建组件。它维护一个当前支付方式状态，初始值为 `PAYPAL`。PayPal 与 TRC20-USDT 各自是一张可访问的单选卡，只显示图标和渠道名称；卡片不再包含渠道说明、Sandbox 状态标签或独立按钮。

页面在两张卡之后渲染唯一的全宽“确认支付”按钮。点击该按钮才调用既有 `createPaymentOrder({ amount, method })`，其中 `method` 为当前选中方式。金额无效或请求进行中时按钮禁用并显示既有 loading 状态。卡片切换本身不得创建订单。

## 文案与金额

- `purchase.copy` 的中英文文案修改为“选择金额，确认支付后，等待额度到账。”的等义文本；门户购买标题和控制台充值页说明继续共用这一翻译键。
- PayPal 和 TRC20 结账摘要的 `payment.quotaEquivalent` 不再使用 `quotaToCredit`。改为传入订单 `amountUsdMinor` 格式化后的美元金额，中文显示“预计入账 $25”，英文显示“Expected credit: $25”。
- 支付完成状态可继续使用内部 quota 的现有语义，不在本次变更中修改。

## 访问性与验证

支付卡使用原生 radio input 或等效的 radio 角色、名称、选中状态和键盘操作。图标替代文本保持 PayPal 与 TRC20-USDT。测试先覆盖默认 PayPal、点击 TRC20 后单次确认请求的准确 payload、渠道说明/旧按钮消失、统一按钮文本，以及两个结账摘要使用美元金额。随后运行支付相关测试、全量前端测试和生产构建。
