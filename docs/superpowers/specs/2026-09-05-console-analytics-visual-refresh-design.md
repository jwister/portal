# 控制台数据分析与视觉升级设计

## 目标

将控制台从基础表单和表格页面升级为统一的数据工作台：所有控制台页面使用一致的图标、卡片、信息层级和空状态；仪表盘使用真实 New API 用量数据提供可操作的图表视图。

## 数据边界与接口

- 新增 portal BFF 接口 `GET /api/console/dashboard/analytics?range=30d`，只接受受控的 `7d` 和 `30d` 时间范围，默认 `30d`。
- BFF 使用当前 portal 会话解析出的 New API 身份和访问令牌请求官方个人统计接口 `/api/data/self`。浏览器不直接访问 New API，也不接触其令牌。
- `/api/data/self` 的逐小时 `quota`、`count`、`token_used`、`model_name` 记录由 portal 聚合为：
  - 每日额度消耗与请求数时间序列；
  - 按额度排序的模型 Top 5（其余合并为“其他”）；
  - 最近 7 天 Token 消耗时间序列。
- 当 New API 未启用数据导出、未返回记录或统计请求失败时，保留账户汇总卡，并在图表区域显示明确的“暂无统计数据”或可重试错误状态；不得展示模拟数据。

## 仪表盘

- 页首保留刷新操作，增加图表范围切换（7 天 / 30 天）。
- 账户汇总区显示可用额度、累计消耗、累计请求、累计 Token 消耗四张带语义图标的指标卡。
- 主图为额度消耗柱状图与请求量折线图的双轴组合图；横轴为按天归并的本地日期。
- 侧栏图为模型消耗 Top 5 环形图，鼠标提示展示模型名、额度和占比。
- 底部图为最近 7 天 Token 消耗面积趋势图；无数据时保持卡片结构，显示空状态。
- 提供“创建令牌”“去充值”“查看日志”三个图标化快捷操作，复用现有控制台路由。

## 统一页面视觉

- 提取可复用的带图标 `MetricCard`、图表容器和增强型页面标题组件；颜色、间距、圆角和阴影通过既有 `styles.css` 中的控制台变量和类统一。
- 令牌管理新增总数、活跃数、受限额度的摘要区；动作使用有文字提示的图标按钮，状态标签采用清晰的语义色。
- 使用日志将筛选区整理为带图标的筛选工具栏；额度、RPM、TPM 摘要使用统一指标卡，表格的模型、令牌与请求 ID 保持层级清晰。
- 个人资料拆为身份卡与偏好设置卡，身份卡展示头像、用户名和邮箱；只读字段继续不可编辑。
- 订单管理增加订单数、待处理、已到账摘要；支付方式在订单或空状态中优先复用 `frontend/src/public` 的已有支付图标，状态标签配合图标和语义色。
- 令牌、日志、资料、订单均采用响应式栅格；移动端自动切为单列、图表按容器尺寸重绘。

## 前端实现与可访问性

- 添加 `echarts` 依赖，并按需注册折线、柱状、饼图及必要组件，避免引入完整图表包。
- 封装可复用的 React 图表组件：挂载后初始化、监听容器尺寸、卸载时释放实例；遵循系统“减少动态效果”偏好，关闭图表动画。
- 图表容器提供文本标题、摘要或数据表等非视觉替代信息，图标按钮有可访问名称或 Tooltip。
- 新增中英文翻译键；所有用户可见文案均经 i18n 输出。

## 验证

- 后端测试覆盖 analytics 聚合（空数据、跨天归并、Top 5 与其他、受控范围）和会话鉴权。
- 前端测试覆盖图表区的数据、空状态和错误状态，以及各页面新增的关键摘要、图标操作和支付图标。
- 运行后端 Maven 测试、前端 Vitest 全量测试和生产构建；使用桌面与移动宽度检查图表及表格布局。

## 非目标

- 不修改 `new-api` 项目或直接从浏览器调用 New API。
- 不提供管理员全站统计，只展示当前登录用户可见的数据。
- 不改变支付结算、令牌权限、日志数据的既有业务规则。
