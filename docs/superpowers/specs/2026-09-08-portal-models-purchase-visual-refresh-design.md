# Portal 模型目录与购买页视觉焕新设计

## 目标

以 "Quiet Ledger" 为统一视觉方向，重做 Portal 的模型目录、模型详情、购买选择和 PayPal／TRC20 结账页面，让它们看起来像可靠、清晰的用量账本；保留既有接口、模型数据、金额校验和支付状态机。

## 范围与边界

- 包含：`/models`、模型详情弹窗、`/purchase`、金额和支付方式选择、PayPal 结账、TRC20 结账。
- 不包含：公共导航、控制台页面、后端 API、支付订单创建参数、PayPal SDK 装载和 TRON 链上核验逻辑的行为修改。
- 既有的翻译键继续使用；本次不改变业务文案语义。

## 视觉系统

页面使用暖白纸张背景、深墨绿文字和森林绿重点色。主要 CSS 自定义属性集中在页面作用域内，避免影响控制台和首页：

| Token | 值 | 用途 |
| --- | --- | --- |
| `--ledger-paper` | `#f5f7f3` | 页面背景 |
| `--ledger-ink` | `#13231d` | 标题和正文 |
| `--ledger-muted` | `#62716a` | 次级说明 |
| `--ledger-green` | `#13855d` | 已选状态、主要操作 |
| `--ledger-line` | `#d7e0d9` | 分隔线与卡片边界 |

排版以现有的 Georgia 标题和等宽金额/模型名为基础，不引入外部字体下载。卡片采用细边、克制阴影与 12–18px 圆角；悬停只使用短暂的上移和阴影变化，并在 `prefers-reduced-motion` 下禁用。

## 模型目录与详情

模型页顶部改为响应式双栏：左列是实时目录标签、标题和说明，右列是模型数量、分组数量及目录在线状态的摘要账卡。桌面端的模型分组保留为左侧可见筛选，搜索框、当前结果数和分组筛选组成带边界的工具栏；移动端将其顺序收为首屏摘要、横向可滚动分组和全宽搜索。

模型卡强调模型名、输入/输出/缓存的单价账格和供应商标签。无定价模型仍显示原有不可用信息，不伪造价格。复制和详情按钮保留原有可访问名称与行为。详情弹窗采用相同颜色变量：头部显示模型身份，价格仍使用三个账格，分组和供应商信息收在有明确标签的说明区，复制按钮使用森林绿主操作。

## 购买与结账

购买页使用具有订单感的窄主栏。金额选择标为第一步；当前选择金额在独立摘要中持续显示。支付方式标为第二步，PayPal、TRC20 和不可用的其他方式有不同的状态与说明，但继续使用现有按钮触发 `createPaymentOrder`，传参和禁用规则不变。

PayPal 和 TRC20 结账容器共享订单摘要风格：订单金额、支付渠道、当前状态和下一步说明在页面顶部稳定可见。TRC20 地址、精确金额、确认进度和 TxID 核验区域维持现有内容与轮询；PayPal 按钮加载、渲染失败和完成后的状态维持现有逻辑。返回修改金额操作始终位于结账内容之后。

## 可访问性与响应式

- 不以颜色单独表达可用、选择或失败状态；状态标签仍包含文字。
- 保留现有 `aria-labelledby`、错误 `role="alert"`、按钮可访问名称和键盘交互。
- 760px 以下收为单列，金额按键至少保持现有尺寸；窄屏时支付方式和价格账格不溢出。
- 所有新增动画尊重减弱动态偏好。

## 验证

实现按测试先行：先为模型页目录摘要、购买页步骤/金额摘要和结账页摘要容器添加可观察的组件测试，确认测试在结构加入前失败；随后实施最小 JSX 结构与 CSS，并运行相关 Vitest 测试、完整前端测试和生产构建。最后在桌面与 375px 宽度下人工检查模型加载、搜索/分组、复制、详情、金额选择、两种支付方式创建和结账状态。
